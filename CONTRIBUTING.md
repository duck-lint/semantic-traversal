# Contributing

Semantic Traversal is currently maintained as a focused personal research and development project.

## What is welcome

GitHub issues are welcome for:

- reproducible bugs;
- incorrect documentation;
- security-neutral failure cases;
- architecture criticism;
- retrieval and evaluation results;
- platform compatibility reports;
- focused feature proposals;
- questions that expose an unclear contract.

Concrete evidence is especially useful. Include the relevant command, runtime outcome, sanitized diagnostics, expected behavior, actual behavior, operating system, Python version, and configuration details that affect the result.

Do not attach private vault content, API keys, personal filesystem paths, or unredacted thread artifacts.

## Pull requests

Pull requests are **not currently solicited**.

The project is moving through tightly coupled architectural seams, and accepting code contributions would imply a review and maintenance process that does not yet exist. Unrequested pull requests may be closed without review.

A well-scoped issue is the best way to propose a correction or design change. Code excerpts or patch sketches may be included in the issue when they clarify the proposal.

## Design discussion

When raising an architectural issue, separate:

- the observed behavior;
- the claimed problem;
- the relevant contract or authority boundary;
- the proposed change;
- what evidence would show the change helped;
- what could falsify or weaken the proposal.

“Use a smarter model” is not, by itself, a sufficient architectural diagnosis.

## Security

Do not report vulnerabilities publicly. Follow [SECURITY.md](SECURITY.md).

## Conduct

Be direct, specific, and civil. Critique the design and evidence rather than the competence or motives of other participants.

Spam, promotional issues, vague AI-generated feature lists, and demands for support may be closed without response.
